Crisis messaging for the network you have left.

A family's status report is eight characters. Forty-five of them fit in one SMS. And if the phone is dead, the same message can be read off a printed card by hand.

mayamoho.github.io/bornomala · github.com/Mayamoho/bornomala

01 — the night the network went

In July 2024 the state cut 3G and 4G.

Broadband went dark. What survived was 2G — voice and SMS. People fell back to text.

Every crisis tool assumes it can build a new network. In July, nobody could.

Bangladesh has fought this fight before. 1952 was the right to speak Bangla. 2024 was the right to speak at all.

02 — the problem, precisely

It costs 2.3× more to be Bangla in a crisis.

Bangla is not in the GSM-7 alphabet. Every Bangla SMS is forced into UCS-2 encoding:

160characters per segment, English
70characters per segment, Bangla
2.3×more expensive, per message

More segments means more cost, more retries, and more failures on a congested network — exactly when SMS is the only channel left.

03 — the thing that is actually different

Don't rebuild the network. Shrink the message.

Most crisis messaging tries to build a new transport — mesh, Bluetooth, Wi-Fi Direct. All of it needs both phones running the same app, in range, with battery.

Bornomala assumes you cannot build a network, and makes the message small enough that the broken one you still have is enough.

Same fight as 2024, one layer down — in the character encoding.

04 — how it works

A language model, an arithmetic coder, and GSM-7.

  • A small statistical Bangla model, trained offline, ships as integer probability tables.
  • A deterministic integer arithmetic coder turns the message into bits — the same bits on every device, or decoding would be worthless.
  • The bits are packed into GSM-7 septets, so a coded message rides the 160-character lane instead of the 70-character one.
  • The phone's own SMS composer sends it. No server, no internet, no message leaves the device.

06 — the honest problem, and the answer

A survivor does not have the app.

Compression needs the app on both ends. That is the same bootstrap trap the mesh projects have — so Bornomala does not pretend otherwise. It ships a second path that needs nothing:

  • Emergency tab — plain text. Type the situation, add a ready sentence, where you are, and when. It goes out as words any phone can read, app or no app.
  • Nine national hotlines — 999, 1090, 102, 333 and more — each one call or SMS away, with the message already written.
  • Location that survives no-data: a maps link and the bare coordinates beside it, because the numbers work when the link cannot load.
  • Relay: a volunteer collects many households' reports and sends them as one SMS.
  • QR handoff for phone-to-phone with no network at all.

Coordinators and relay volunteers install it. Survivors never have to.

07 — graceful degradation

Every layer below has a floor.

No internetinstallable offline PWA, precached shell, no server anywhere in the design
No dataSMS over 2G; bare coordinates travel beside every map link
No networkQR handoff, screen to camera
No phonethe code is printable — decodable off a card by hand

No framework, no dependencies, no analytics, no accounts. The whole app is a handful of files and a 1.7 MB model, and it runs on a low-end Android with a dying battery.

08 — status

Working, tested, and live.

  • Installable PWA, running now at mayamoho.github.io/bornomala
  • Full interface in Bangla and English, switchable mid-message
  • 57 automated checks — codec round trips, send paths, offline shell, translation parity
  • MIT licensed, reproducible benchmark, model training tools in the repo

One number worth remembering: 5.1× more Bangla in every SMS, on the network that was left.
