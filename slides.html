July Hackathon 2026 · Track A — Crisis Tech · solo entry

বর্ণমালা · Bornomala

An offline Bangla SMS app with three jobs: compress ordinary messages so 5× more fits in one text, compose emergency reports any phone can read, and let one volunteer relay many households' reports in a single SMS.

Everything runs on the phone. No server, no internet, no account, no message ever leaves the device except through your own SMS app.

mayamoho.github.io/bornomala · github.com/Mayamoho/bornomala

01 — the night the network went

In July 2024 the state cut 3G and 4G.

Broadband went dark. What survived was 2G — voice and SMS. People fell back to text.

Every crisis tool assumes it can build a new network. In July, nobody could.

Bangladesh has fought this fight before. 1952 was the right to speak Bangla. 2024 was the right to speak at all.

02 — the problem, precisely

It costs 2.3× more to be Bangla in a crisis.

Bangla is not in the GSM-7 alphabet. Every Bangla SMS is forced into UCS-2 encoding:

160characters per segment, English
70characters per segment, Bangla
2.3×more expensive, per message

More segments means more cost, more retries, and more failures on a congested network — exactly when SMS is the only channel left.

03 — the thing that is actually different

Don't rebuild the network. Shrink the message.

Most crisis messaging tries to build a new transport — mesh, Bluetooth, Wi-Fi Direct. All of it needs both phones running the same app, in range, with battery.

Bornomala assumes you cannot build a network, and makes the message small enough that the broken one you still have is enough.

Same fight as 2024, one layer down — in the character encoding.

04 — how it works

A language model, an arithmetic coder, and GSM-7.

  • A small statistical Bangla model, trained offline, ships as integer probability tables — 1.7 MB, 152 symbols, three context orders.
  • A deterministic integer arithmetic coder turns the message into bits — the same bits on every device, or decoding would be worthless.
  • The bits are packed into GSM-7 septets, so a coded message rides the 160-character lane instead of the 70-character one.
  • The phone's own SMS composer sends it. No server, no internet, no message leaves the device.

05 — tab one: Normal

Write Bangla, watch it shrink, send it.

  • Write in Bangla. Four live counters update on every keystroke: characters, GSM-7 segments the coded form needs, segments the same text would cost today in UCS-2, and the ratio between them.
  • The compressed message appears as a short GSM-7 string, with its exact cost in septets and bits per character.
  • Send hands it to the phone's SMS composer, already addressed and filled. The recipient number is required — a number-less SMS link is silently refused by most phones, so the button stays off rather than pretending.
  • Open a message you received: paste the code and the original Bangla comes back. Paste the whole received SMS — attribution line, map link and all — and it still finds the code.
  • Text shared into the app from any other app lands in the decode box automatically.

06 — the honest problem, and tab two

A survivor does not have the app.

Compression needs the app at both ends — the same bootstrap trap the mesh projects have. So the Emergency tab uses none of it. It sends plain Bangla any phone can read, and it refuses to send until the message is actually useful to a responder:

  • What is happening — typed in your own words. Required.
  • A ready sentence — 32 of them in four groups (status, need, danger, help offered), six on icon buttons for the ones reached for first. Each carries fill-in values: how many people, how urgent, blood group, flood depth, shelter capacity.
  • Where you are — 64 districts, or live GPS. Required.
  • When — just now, or up to 31 hours ago. Required.
  • Nine official national hotlines — 999, 1090, 102, 16263, 333, 109, 1098, 16430, 106 — each one tap from a call, or from an SMS with your message already written into it.

A live preview shows the exact text that will leave the phone, with its character and segment count. Coordinators and volunteers install the app; survivors never have to.

07 — tab three: Relay

One volunteer, forty households, one SMS.

A volunteer at a shelter collects status from the families around them. Each report is added from the Emergency tab with one tap, and the whole queue goes out as a single message.

  • The queue lists every report, each removable, with a running count.
  • Four counters show what it costs: reports, characters, segments as one batch, and — the number that makes the case — how many segments the same reports would have cost sent one at a time.
  • Send to one number, or copy the batch out. Same required-recipient rule.

Batching is not a micro-optimisation here. On a saturated tower, one message that goes through beats forty that queue.

09 — graceful degradation

Each layer below has a floor.

No internetinstallable offline PWA, precached shell, no server anywhere in the design
No mobile dataSMS over 2G, through the phone's own composer
No GPSlocation falls back from live coordinates to a district you pick
No network at allshow the QR, let the phone beside you point a camera — no radio, no pairing

Location always travels twice: a maps link and the bare coordinates beside it, because the numbers still work on a phone that cannot load the link.

No framework, no dependencies, no analytics, no accounts. The shell is 92 kB; the model is 1.7 MB and loads separately, so the Emergency and Relay tabs work before it arrives.

10 — status

Working, tested, and live.

  • Installable PWA, running now at mayamoho.github.io/bornomala
  • Full interface in Bangla and English, switchable mid-message without losing what you typed
  • 81 automated checks in three suites — codec unit tests, a headless run of the whole interface, and a project audit (offline shell, translation parity, dead ids)
  • MIT licensed, reproducible benchmark, model training tools in the repo

One number worth remembering: 5.15× more Bangla in every SMS, on the network that was left.
